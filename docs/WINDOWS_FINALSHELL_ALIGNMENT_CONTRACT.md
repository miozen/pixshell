# Windows FinalShell 对齐改造契约

- **状态**：Proposed（计划已固化；实施范围须逐阶段确认）
- **适用端**：仅 `win/`；不得为本计划改动 macOS 代码。
- **目标**：借鉴 FinalShell 的高频工作流，提升 Windows 端 SSH/SFTP/快捷命令效率；不复制其代码、资源、品牌或专有 UI。
- **权威性**：本文件是该改造的范围、阶段和验收来源。架构约束见 [ARCHITECTURE.md](ARCHITECTURE.md)，全局决策见 [DECISIONS.md](DECISIONS.md)，实时接力状态见 [HANDOFF.md](HANDOFF.md)。

## 已确认目标

1. Windows 端远端文件应支持双击后以图形化弹窗编辑、保存回传，不要求用户使用 `vi`/`vim`。
2. 用户收藏的快捷命令应可调整显示位置，而不只是移动到其他分组。
3. 改造应优先复用现有 Windows 架构和功能，不以“功能对齐”为由进行大规模重写。

## 现状基线

远端文本编辑并非空白功能：`SftpPanel` 已在双击文件时下载临时副本、打开 `EditorWindow`，保存后上传回原路径。当前上限为 4 MiB，读取优先 UTF-8、失败回退 Latin-1；保存失败会保留编辑窗口和脏状态。

快捷命令已支持分组、参数模板、发送到当前/全部已连接/指定会话及“移动到分组”，但 `QuickCommand` 没有排序字段，`QuickCommandStore.List()` 按 JSON 插入顺序返回，故不支持同组位置调整。

## W5：远端新建文件（已确认）

- 入口：远端文件列表右键菜单和底部坞工具栏均提供“新建文件…”。
- 名称：允许任意文件扩展名、无扩展名、Unicode 与以 `.` 开头的常见文件名；只接受单个文件名，拒绝空白、`.`、`..`、NUL、`/` 与 `\\`，不得把输入解释为相对或绝对路径。
- 创建：只在当前远端目录创建零字节文件；如果同名文件或目录已经存在，必须失败并保留既有对象，不能覆盖、截断或复用上传逻辑。
- 完成：创建成功后刷新当前目录、选中该文件并通过既有编辑器打开；编辑器不支持的内容仍遵守既有大小/编码与保存失败保护规则。
- 后端：SSH.NET 使用独占创建；系统 SFTP/Proc 使用 SFTP 独占创建请求；SCP 回退使用安全转义的远端 shell 创建并明确检测冲突。现有 Proc SFTP 的目录和删除元操作也必须从静默空操作补齐，不能向 UI 报假成功。
- 验收：分别验证 `.env`、`config.json`、无扩展名与 Unicode 名称；同名文件/目录不覆盖；权限失败有明确反馈；SSH.NET、Proc 与 SCP 后端不静默成功；创建后可打开、保存并在刷新后可见。

### 远端删除补充语义（D-015）

- 空目录直接删除；若目录非空，必须先列出检测结果并要求“递归删除”二次确认。取消或目录列举失败时，不得删除任何目标。
- 二次确认后，客户端逐层删除子项再删除目录，以保证 SSH.NET、Proc SFTP 和 SCP 回退的结果一致；目录符号链接按链接项删除，不递归跟随；任一目标失败必须显示名称与错误。

## W2：SFTP 可靠性（已确认分阶段范围）

### W2a：任务、进度与安全下载落盘（已确认）

- 建立进程内统一传输任务模型，覆盖直传上传和下载，显示方向、状态、已传输字节、总字节和失败详情；任务不持久化，应用退出或会话断开后不能标作可恢复。
- 直传下载一律先写入同目录的 `.pixshell.part` 临时文件；只有传输成功且关闭文件句柄后才替换最终文件。失败保留 `.part` 供 W2b 使用，不能截断已有完整目标。
- 若最终本地文件已存在，必须明确提供“覆盖 / 另存为 / 取消（跳过）”选择，默认不覆盖。失败任务可从工具面板重新发起同一操作。
- 不在 W2a 宣称取消或断点续传；打包传输仍维持原有路径，不接入文件级续传或覆盖策略。
- 验收：上传和下载可见任务与进度；失败显示详情且可重试；下载失败不改写原最终文件；另存为不冲突；既有 SFTP/SCP/系统 SFTP 后端仍可用。

### W2b：单文件直传取消与断点续传（已确认）

- 仅覆盖单文件直传。取消在当前分块完成后生效，保留本地/远端临时文件，最终目标保持不变；本次应用运行期间可继续或重新开始，不承诺跨重启恢复。
- 下载从 `.pixshell.part` 现有偏移继续；上传先写同目录远端临时文件，成功后改名为最终路径。已有最终目标必须明确选择覆盖、另存为或跳过。
- SSH.NET 与系统 SFTP 支持续传和协作取消；SCP 回退只支持重新开始，不显示可续传/可取消的虚假状态。

### W2c：打包传输语义（已确认）

- 本地 tar 打包/解压、SFTP 传输阶段接入取消任务；远端 tar 已启动后仅在返回后尽力清理，不能承诺立即终止。
- 打包下载先解压到本地唯一临时目录，再按顶层条目选择覆盖、跳过或取消；打包上传先解压到远端唯一临时目录，冲突条目默认跳过并反馈数量。
- 成功和失败均尽力清理本地/远端临时包和临时目录；不承诺压缩包断点续传、跨重启恢复或逐文件续传。

## W4：效率与监控增强

W4 已按 [D-008](DECISIONS.md#d-008w4-分阶段交付) 拆分实施；W4a/W4b 已实现，W4c 的已确认执行语义见 [D-009](DECISIONS.md#d-009w4c-已连接会话批量执行语义)。

### W4a：监控时间窗与网卡选择（已确认）

- 保持既有三秒单飞采样，不增加远端 `sleep`、轮询频率或后台任务。
- 网络和延迟图表可选择 1、3、5、15 分钟窗口；切换窗口清空历史样本，防止不同窗口比例混合。
- 监控命令返回非回环远端接口列表；默认“自动”保持原先的优先物理接口选择，用户可改选其中一张网卡。
- 切换、消失或自动选择改变时，网络曲线从下一拍重新计算；接口名仅在满足 Linux 接口名白名单时才会进入远端命令。
- 验收：窗口切换不提高轮询频率；自动/指定接口均显示正确上下行；切换会清空旧曲线；断线、切会话和不支持 `/proc/net/dev` 的服务器安全退化；命令广播语义不变。

### W4b：命令建议（已确认）

- 入口：命令栏“建议”按钮与 `Ctrl+Space`；不会在输入时自动弹出或请求远端。
- 数据源：本地命令历史和已保存快捷命令；按前缀优先、去重并限制候选数。快捷命令可按名称匹配，但回填其命令模板。
- 选择语义：只将候选文本回填命令框；只有用户随后按 Enter 或“发送”才会执行。不得调用 `OnSendTo`、改变当前/广播目标或向 SSH 发出请求。
- 路径：现有 Tab 远端路径补全保持独立；建议菜单只提示该入口，不替代或隐式调用它。
- 验收：历史/快捷命令过滤与排序正确；选择候选不发送命令；无匹配时给出明确反馈；Tab 补全和现有历史菜单仍可用。

### W4c：批量主机任务（已确认）

- 目标：只显示当前已连接的 GUI 会话，用户必须在执行前显式勾选目标；不自动连接离线主机，不使用 Agent 会话池。
- 执行：命令走每会话独立 `ExecAsync` 通道，不写入交互 shell；最大并发 3；单台失败继续剩余目标。
- 参数：沿用普通命令的 `${参数}` 一次性取值，所有选中目标使用同一解析结果。
- 结果：完成后在独立结果窗口按会话展示成功/失败和输出；每台输出上限为 12,000 字符，超出部分明确标记截断。
- 非目标：取消/重试队列、离线主机自动连接、持久化任务、定时任务与后台常驻执行均不属于本切片。
- 验收：只能选择已连接会话；选择目标不发送命令；并发不超过 3；一台失败不取消其余任务；结果可区分每台状态；既有当前/全部已连接广播语义不变。

## F0：质量、构建与分支交付契约

### 分支规则

- `main` 不承载日常功能开发，也不直接接收功能切片。
- `dev` 是远程集成分支，`origin/dev` 已由 F0 建立；不得直接推送 `main` 作为功能切片的替代。
- 每个切片完成后，必须更新 `CURRENT_PLAN.md` 与 `HANDOFF.md`，提交并推送到 `dev`；并行工作可先经 `codex/<slice>` 主题分支合并到 `dev`。
- 仅当 `dev → main` 的 CI、产物与验收全部通过且用户明确批准时，才可合并发布分支。

### GitHub Windows CI

- 当前 `build.yml` 已能在 Windows runner 进行 self-contained publish、压缩包和 Inno Setup 安装包构建，且支持 `workflow_dispatch` 手动触发；自动触发范围只覆盖 tag 与面向 `main` 的 PR。
- F0 必须增加 `main` push 自动构建，同时保留 tag 与面向 `main` 的 PR 检查；**不得**为 `dev` push 或面向 `dev` 的 PR 增加自动完整构建。`dev`/主题分支需要安装包时，由操作者在 Actions 页面手动触发并选择对应 ref。
- 成功 CI 至少应保留 Windows x64 的 zip 和 setup 安装包为可下载 artifact；发布到 GitHub Releases 仍仅由 tag/发布流程触发。

### 最小自动化测试层

不要求在改造前重写成完整测试体系，但 F0 后每个切片必须具备与风险相称的自动化验证。

1. 建立可由 `dotnet test` 调用的 Windows 测试项目或等价测试入口，并接入 CI。
   本地统一入口为 `cd win; ./build.ps1 -Action test`。
2. 首批覆盖纯逻辑、无 UI 依赖的 `QuickCommandStore`：旧 JSON 兼容、组内排序、跨组移动、新增/删除后的顺序稳定、参数渲染不变。
3. SFTP 编辑器等 UI/远程 I/O 流程采用可重复的手工验收清单；可抽离的编码、大小限制、保存成功/失败状态逻辑再逐步单测。
4. 每个切片至少执行：相关 `dotnet test`、Windows `dotnet publish` 或 `win/build.ps1` 发布检查、与功能对应的手工验收。

### F0 验收

- `origin/dev` 存在，且开发切片不会直接合并/推送到 `main`。
- GitHub Actions 在 `main` push 与面向 `main` 的 PR 时自动运行 Windows 构建、测试和安装产物检查；`dev` 无自动完整构建。
- 操作者可通过 `workflow_dispatch` 对 `dev`/主题分支手动运行相同 Windows 构建；CI 产物包含 `PixShell.exe`、WebView2 依赖、xterm 资源、zip 与 setup 安装包。
- 本地或 CI 的 `dotnet test` 能运行至少一组快捷命令持久化/排序回归测试。
- Handoff 能指出当前 `dev` HEAD、是否已推送、CI 运行链接/结果和安装包 artifact 状态。

## W0：远端编辑契约

- 入口：远端 SFTP 文件双击或右键“打开”。目录仍进入目录，不能误作为文本打开。
- 保存：仅在上传成功后清除脏状态；失败必须保留内存中的用户修改并显示可操作错误。
- 安全与兼容：不得把远端密码、私钥或完整文件内容写入日志；临时文件必须在正常/失败路径尽力清理。
- 非目标：不做二进制编辑、协同编辑、Git diff、完整 IDE 或无限大文件编辑。
- 后续可选项：编码选择、只读预览、外部变更冲突检测、图片/PDF 预览和代码折叠，均不属于 W0。

## W1：快捷命令排序契约

- 排序范围：先只承诺**同一分组内的命令顺序**；分组自身排序是独立候选项。
- 操作：提供可访问的“上移/下移”操作，并提供拖拽排序；拖拽不能是唯一方式。拖拽仅在当前单一分组视图中生效，拖到某命令上表示插入其前，拖到列表空白处表示追加到本组末尾；“全部”视图不允许拖拽改变顺序。
- 持久化：每个命令使用向后兼容的 JSON `sortOrder` 表示同组顺序；已有 `quick-commands.json` 缺少该字段时，必须保留全部命令、分组、参数和原 JSON 相对顺序，并在下一次排序相关写入时生成连续排序值。
- 一致性：新建命令追加到当前分组末尾；删除命令后相邻顺序稳定；“移动到分组”必须定义其落点（默认目标组末尾，除非 UI 另行选择）。
- 发送不变量：排序只影响展示顺序，不改变命令文本、参数渲染、`AutoReturn` 或发送目标。

### W1 集中验证清单（实现后执行）

- 自动化：旧 JSON 无 `sortOrder` 的读取顺序；上移/下移边界；同组拖拽重排与重启持久化；跨组拖拽拒绝；“移动到”目标组末尾；参数渲染回归。
- Windows 手工：右键/齿轮的上移、下移和边界禁用；同组拖拽到命令前与空白末尾；“全部”视图不可拖拽；编辑、发送及跨组移动不受排序影响；重启应用后的顺序。
- 交付：`win/build.ps1 -Action test`、Windows publish/安装包构建，以及按需手动触发 `dev` 的 GitHub `build` 工作流。未执行前均为 pending，不得当作通过。
